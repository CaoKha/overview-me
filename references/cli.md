# The overview-me CLI

The skills call the plugin root `<root>`. The CLI is `<root>/bin/overview-me`, written `overview-me` in the skills. In Claude Code the plugin installs it when a session starts; in other agents it is installed the first time a skill runs, as below.

- Before the first CLI call of a run, run `bash "<root>/scripts/ensure-cli.sh"`. It returns at once when the binary matches the plugin version; otherwise it downloads the release for this machine or builds it from source.
- If it is still missing, tell the user what the script printed and stop.
- Run it from the root of the repo under review.

| Command | What it does |
| --- | --- |
| `overview-me base [<pr>]` | Prints `base`, `head`, `mode` (`pr`, `branch` or `uncommitted`) and `pr`: the named PR (fetched, not checked out), else the checked-out branch's PR, else the branch against the default branch. |
| `overview-me path [--head <sha>]` | Prints where the map for a head commit lives. Its folder is `<store>`. |
| `overview-me extract --base <sha> [--head <sha>] [--spec <file>] [--fresh] [--group-by dir|symbol] [--depth N] [--split <prefix>] [--path <prefix>] [--map <file>]` | Writes the facts and the draft map for `base...head` (keeps a map only for matching base, head, path and grouping unless `--fresh`). Above 300 draft nodes, groups by folder (depth 2), prints totals and the biggest folders, and prunes weighted calls to two per caller, 15 total. `--split` repeats in priority order; first matching path prefix wins. `--group-by symbol` disables automatic grouping. `--path` scopes coverage and requires `--map`. Facts default to `<map-stem>.facts.json` beside a custom map; `--out <file>` overrides that. Changed grouping settings write a new draft. Below the threshold, prints each node’s diff and test declarations. |
| `overview-me node <id> [--map <file>]` | Prints the changed hunks, deletions and moves owned by one node (default map: HEAD). |
| `overview-me validate <map.json>` | Checks a map against the schema and git. Prints `ok`, or exits 1 with the problems. |
| `overview-me flow <map.json>` | Draws the Before and After flow diagrams from the code into `<store>/<head>.flow.json`, and prints entry points, unchanged callers and callees, and removed symbols still referenced. |
| `overview-me render <map.json> [--change --scope <text>] [--fresh] [--findings]` | Validates the map, runs `flow`, and writes the overview page `<store>/<head>.review.md` with `<!-- fill: … -->` slots. Refuses to overwrite a page unless `--fresh`. With `--findings`, adds a Findings section from `<store>/<head>.findings.json`; on an existing page it writes only that section and keeps the rest. |
| `overview-me findings <map.json> <review file> [--head <sha>]` | Reads OpenCodeReview JSON (or the same `comments` written by a host agent) or SARIF 2.1.0. Refuses a review of any commit but the map's head; `--head` names the commit when the file does not. Puts each finding on the node whose sites hold its lines, lists the ones outside every site, rejects those whose file, lines or quoted code are not at head, and writes `<store>/<head>.findings.json`. |
| `overview-me snapshot` | Prints a commit holding HEAD plus every uncommitted and untracked file, without touching the branch, the index or the files. |
| `overview-me page <file.md> [--unpushed] [--theme <file.css>]…` | Writes the overview as an HTML page next to it. Each `--theme` adds a palette stylesheet to the page's palette picker (format in `DESIGN.md`); a file holding `</style` is refused. Fills ```` ```flow ```` blocks holding `@before` or `@after` from the flow file. With a `## Findings` section, shows `<store>/<head>.findings.json` on the After flow: a badge per box, and the findings in its panel. Exits 1 when a `flow` block is invalid, a slot is left, a `path:line` points at no line (for a finding, only its place is checked), a node id is not in the map, an open question cites nothing, or a Findings section has no findings file. |
